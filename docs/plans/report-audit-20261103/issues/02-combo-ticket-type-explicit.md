# 02 组合推荐票型显式化

Type: task
Status: resolved (PR #216, 2026-11-03)

## Question

组合卡展示"至多两笔独立单关"（各 20 元、总 40 元、EV 合计 3 元），一键带入
却变成一注 2 串 1、注金取第一腿（20 元）——确认前后票型、成本、收益分布发生
漂移（现仅靠 toast 提示自认）。是否让用户显式选票型，预览与执行同一套票级
计算？

## 事实（2026-11-03 main 实测）

- `web/src/lib/combo-engine.ts:45` `maxPicks: 2`；199-208 各 pick 为独立单关
  （stake + ev×stake）；220-221 总注 = Σstake、EV = ΣexpectedProfit
- `web/src/pages/market-had-page.tsx:56-68` `applyCombo`：两个 pick 塞进同一
  bet 的 legs（一注 2 串 1），stake = `picks[0]?.stake`（仅第一腿注金）；
  toast 63-64 自认"组合卡按两条独立单关口径……篮子按一注 2 串 1 提交"
- `web/src/components/had-basket.tsx:94-106,108` 单 bet 双腿提交，标签 2 串 1

## 验收

1. 带入前显式选择"两笔单关"/"一注 2 串 1"，各票型预览总注 / 联合 EV / 命中
   条件并列展示，不再默认静默切换
2. 所选票型的预览数 == 提交后落库口径（票级计算单源，同一函数）
3. 2 串 1 联合 EV 用 (1+EV₁)(1+EV₂)−1 口径（报告路线 C），与单关合计口径
   并列，两口径语义注释进代码
4. 黄金样例：两腿赔率 2/3、EV 10%/5%、各 20 元 → 单关合计 40 元 / EV 3 元；
   2 串 1（20 元注金）EV = 20×(1.10×1.05−1) = 3.10 元——两口径都有测试钉死

## 不变量与人裁决项

- 人裁决：默认票型（推荐记住上次选择；无历史默认单关合计 = 引擎本义）
- 一键带入交互形态（选择器 vs 双按钮）留给实现
