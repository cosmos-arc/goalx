# 01 任九组合与计价统一

Type: task
Status: resolved (PR #215, 2026-11-03)

## Question

任九复式票据的注数、组合与金额前后端不一致：后端 `materialize_combinations`
对全部所选场次做笛卡尔积（10 场单选 = 1 条十场腿组合、2 元），前端却按
C(n,9) 展示（10 注 20 元）。是否按"后端单源生成 9 选子集 + 预览计价、前端
只消费后端数"收口，并用黄金样例钉死三方一致？

## 事实（2026-11-03 main 实测）

- `betting/store.py:406-469` `materialize_combinations`：total 为逐场 picks
  连乘（431-433），`_combination_rows`（459）= `product(全部所选场)`，无
  "从所选场次中取九场"子集逻辑
- `api/bets.py:92` docstring 自述"picks 笛卡尔积 materialize 为组合"
- 前端 `market-pool-page.tsx:54-64,109` 组合数 = 客户端自算
  `combinations(n, 9)`，290/348/406 展示"N 注 × ¥2"
- `SlipView`（`api/bets.py:153-163,457-458`）只聚合 bets 表，组合数不回读
  对账——展示 / 落库 / 回读三面各说各话
- `pool_period_id` 已修（传 `detail.pool_period_id`）；池票 paper-only 三层闸
  在位（`api/bets.py:497-500` 后端 400 + 前端红线注释）
- 资源上限在位：复式组合 10 万上限（PR #213 票 07）——任九复式
  C(14,9)×2^9 ≈ 102.5 万会撞闸，超限行为须定义

## 验收

1. 任九（n≥9）：组合 = 全部 9 场子集 × 各子集内逐场 picks 之积；14 场
   （ttt14）= 整体 14 腿不动
2. 预览端点返回注数 / 总金额 / 组合明细（或其可校验摘要），前端展示、
   落库组合、SlipView 回读三方一致
3. 黄金样例钉死：9 场单选 = 1 注 2 元；10 场单选 = 10 注 20 元；14 场单选
   = 2002 注 4004 元；含每场多选与超限样例
4. 超限行为明确（拒绝并报上限 vs 截断 + 标记），落契约
5. 历史已落库的笛卡尔积错误组合行有处置（见人裁决项），处置后账面可对账
