# 07 首页无候选归因面板

Type: task
Status: resolved (PR #221, 2026-11-04)

## Question

首页只有经营指标，不回答"今天为什么没有候选"。报告六类状态：未开售 / 数据
没采到 / 国际参考断供 / 有价但证据不合格 / 信息齐确实无优势 / 有候选来不及
执行。是否分桶展示 + 下钻，让"没有推荐"必有可理解的原因？

## 事实

- 历史事故佐证该需求非假设：换源后消费者读旧命名空间致欧赔共识 / EV 长期
  空（能力登记表在案）；旧 `sellStatus` 解析反向把在售误记停售（PR #184）
  ——"没推荐"长期无法区分断供 vs 无优势
- 数据面判据已有雏形：`quote_evidence` 裁决原因（`stale_source` /
  `jc_no_quote` / `jc_observed_at_unknown` / `jc_three_way_incomplete`）、
  sellStatus 语义已修（1=在售）、轨二快照已起跑（11-01 首 5 行合格）

## 验收

1. 后端聚合端点：按（玩法，日）给六桶计数 + 各桶样本 fixture_id
2. 首页面板展示六桶，点击下钻到对应场次列表
3. 桶判定规则与 `quote_evidence` 裁决原因一一对应（映射表进 docstring +
   契约描述），不新造第二套健康真相
4. 断供类桶与晨检对账一致（晨检九项已有欧赔 / 语料 / 夜班面，复用其数据源）

## 不变量与人裁决项

- 人裁决：六桶口径命名（推荐直接用报告措辞）；"来不及执行"桶是否首期就做
  （依赖截止时间数据，可先空桶占位）
- 桶判定在后端聚合层做（单一事实源），前端只渲染——结构留给实现
