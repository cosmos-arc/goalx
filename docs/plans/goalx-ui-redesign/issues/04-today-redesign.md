## Question

今日页从 12 列大表升级为"机会发现工作台"应该长什么样？用高保真原型（静态页面或组件预览）让用户直接反应：

1. 信息分层：EV 机会优先呈现 vs 全量对照列表，两者的关系（视图切换？机会置顶？）
2. 视觉编码：EV 强度、had 资格判定（可投/拒绝/证据未知）、数据新鲜度三套信号如何在不炸屏的情况下传达
3. 选注篮交互：常驻侧栏/底部抽屉/浮动，与 2串1、同场约束、单固规则的前置传达（现状靠报错文案）

5. 原型须用 02 票的 token 与 03 票的页面命名

约束对齐（02/01 已决，2026-09-16 补记）：**不做全局密度切换**（表格组件级 compact 变体已够）；选注篮形态可评估 Base UI Drawer；EV/资格/新鲜度编码直接用 02 的双层语义 token（钱层红绿、界面层 amber/blue），不再自创配色。

## Answer

2026-09-16 原型过审定稿（原型资产：`proto/ui-04-today` 分支，`/proto/today` 路由，8 场 mock 覆盖全部状态；两轮用户反馈迭代后通过）：

1. **信息分层**：可投卡片置顶（联赛/倒计时/EV 三向+最强标注/快捷选注钮/仅串关标记）+ 全量 compact 表在下；**不做视图切换**（切换藏数据）。卡片区不重复显示"可投"徽章（区块即过滤结果），标题行给"N 场不可投"对照计数。
2. **编码（用户两轮反馈后的修正版，优先级最高的一条）**：EV 数字**永远只按正负红绿**（红涨绿跌），|EV|≥5% 用独立琥珀"偏差"徽章表达、不得抢数字色；资格徽章 蓝=可投 / 红=拒绝+原因 / 灰框=证据未知；新鲜度相对时间（>30 分钟琥珀）折进时间格第二行；T1 徽章中性灰（分层信息≠警示）；页头一行全局数据健康（竞彩/欧赔 N 分钟前）+ 一行配色图例。
3. **选注篮**：底部常驻条（选中摘要 + 组合赔率）→ 右侧 Drawer（Base UI），内含腿列表/移除/金额/模式/建立建议；移动端形态（右侧 vs 底部抽屉）14 号实现时真机验证。
4. **规则前置**：同场换选=直接替换+行内提示（不报错）；2串1 上限满=行内提示；非单固首腿=提示"只能作串关腿"；停售/已开赛=按钮禁用+行 opacity-60 弱化。服务器校验仍为唯一权威。
5. **表格结构**：资格列第 4 位（对阵后，筛行信号前置）；1440 视口无横向滚动；密度=卡片舒适档+表格 compact 档（`data-density`），无全局开关。

给 14 号实现票的输入：原型分支即设计参考；mock 场景清单见 `today-proto-data.ts`；正式实现接真实 API + MSW 测试 + e2e + axe。
