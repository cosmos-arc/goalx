# 06 · 投注生命周期页重设计

Type: grilling
Status: resolved
Blocked by: 02, 03

## Question

建议 → 锁定/真实回录 → 开奖导入 → 结算 → 复盘的生命周期如何在 UI 呈现：

1. 状态流模型：未锁定/已锁定/已结算三段现状是三个分组表，产品化形态选型（状态流看板/时间线/增强分组表）
2. 真实回录表单重构：现在内联挤在表格操作列里，改为模态/侧栏/行展开？实际条款字段（金额/各腿赔率/时点）的录入体验
3. 开奖录入形态：单场表单 → 向导/批量录入/自动拉取留位；影响预览（冲正/重算）的呈现升级
4. 错误与校验前置：竞彩规则（同场不可串、2串1 上限、非单固）从服务器报错前移到交互层
5. 暴露的 API 增量（如批量开奖、状态聚合）记入清单（票 10）

## Comments

- 2026-09-16 预裁决（用户）：**赛果区 = 同步优先，人工兜底**。背景：人工录入是 M1 权宜（sporttery 开奖网关被拒、500.com 彩果解析搁置，见 ingest/results.py 注释），非设计哲学。方向：①后端接入自动赛果源（500.com 彩果页解析或 sporttery 换路径，属 goalx-quant 地图后端工作），落库走现有 import_draw_results（幂等+原子+冲正已具备）；②UI 呈现"同步面板"：上次同步时间/来源、待出赛果场次、**主动触发同步按钮**；③定时兜底 = Prefect 任务晚间窗口轮询（复用 server+serve 双进程调度模式）；④人工录入降级为兜底/更正通道（无效场次、同步冲突、口径异常），更正保留影响预览。API 增量：同步触发端点、同步状态端点、后端 ingest 任务——票 10 汇总时排期，后端开发在 goalx-quant 侧立票。

## Answer

2026-09-17 剩余项定稿（用户"全按推荐"）：

1. **状态流形态 = 增强分组表**：保留三段分组（未锁定/已锁定含真金回录/已结算），组头计数徽章+待办提示，行内状态徽章、时间倒序。生命周期仅 3-4 态，看板过疏、时间线不利批量，分组表 e2e 契约最稳。
2. **真实回录 = 右侧 Drawer**（复用 ui/drawer）：实际金额/逐腿赔率/时点 + 提交前"建议快照 vs 实际条款"对照。不用模态（打断对照）、不用行展开（移动端易碎）。
3. **规则前置补充**：锁定前开赛 <5 分钟警示；live 回录金额≠建议金额时提示"按实际条款记账"；开奖更正必填原因（已有）。同场/上限/单固已于 14 号落地。
