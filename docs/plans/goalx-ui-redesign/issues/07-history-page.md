# 07 · 历史复盘页设计

Type: grilling
Status: resolved
Blocked by: 03

## Question

已结算注的历史查询与盈亏分析页（新增）：

1. 筛选维度：时间范围/联赛/模式（纸面 vs 真金）/策略版本/结果状态的组合筛选
2. 聚合口径：总盈亏、命中率、平均 EV、CLV 摘要——与验证页（前瞻口径、样本约束）的职责去重，本页是"流水视角"还是"分析视角"还是分层兼有
3. 下钻：聚合行 → 注明细 → 场次的路径
4. 后端查询端点需求（分页/过滤/聚合形态）记入 API 清单（票 10）

## 不变量与人裁决项

- 历史页的盈亏口径必须与验证页显式标注差异（哪些注纳入/排除），防止两页数字对不上引发信任问题

## Comments

- 2026-09-16 预裁决（用户）：**分析优先，流水为下钻层**——聚合指标是主界面（总盈亏/注数/命中率/平均 EV/平均 CLV，各带正负号与判读方向），点开聚合行才见注明细；避免沦为"投注页归档版"。筛选两层：常驻 = 时间范围 + 模式（默认纸面）；二层 = Competition / 策略版本 / 结果状态。纸面/真金大标签常显。

## Answer

2026-09-17 剩余项定稿（用户"全按推荐"）：

1. **口径差异标注文案**（页头固定一行）："统计已锁定且已结算的注；前瞻验证口径（含排除规则）见验证页。"——"前瞻纳入"四字接词典 tooltip。两页数字不同时各自以口径标注为准。
2. **聚合区形态**：五指标卡行随筛选联动 + 盈亏累计曲线（ECharts 复用 use-echarts）+ "查看明细"同页展开注列表（不跳页）。
3. **数据源（衔接票 10 定稿）**：v1 用现有 `GET /bets` 前端过滤聚合（个人工具数据量千注级，无压力），零新查询端点；数据量涨到前端吃力再加分页聚合端点。
