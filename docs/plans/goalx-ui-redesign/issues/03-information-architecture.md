# 03 · 信息架构与导航重设计

Type: grilling
Status: resolved

## Question

产品化后的整体 IA：

1. 导航分组与页面命名：总览/今日/投注/历史/验证/资金/词典 + 预留复核/设置——主次导航结构、命名词典（与根目录 `CONTEXT.md` 术语对齐，新术语按 domain-modeling 流程回写）
2. 路由结构：新页面路由、现有路由是否调整（含 e2e/测试路径迁移成本）
3. 核心用户旅程的职责切分：赛日流程（看盘→选注→锁定→录赛果→结算→复盘）每步落在哪页，跨页跳转怎么设计
4. 空状态与首次引导策略：无数据/后端不可用/当日无场次三种状态的产品化呈现
5. 响应式底线：桌面优先，移动可用的最低标准

## 不变量与人裁决项

- 页面命名一旦定下即进导航与测试选择器，改名成本高——命名清单须用户逐个确认
- 竞彩合规表述（如"建议/纸面/真金"的用词）不得在重命名中弱化风险提示

## Comments

- 2026-09-16 预裁决（用户）：**命名词典定稿**——总览 `/`、今日 `/today`、投注 `/bets`、历史 `/history`、验证 `/validation`、资金 `/bankroll`、词典 `/glossary`、复核 `/review`（M3 预留）、设置 `/settings`（M4 预留）。六个现有名全保留；历史页刻意不叫"复盘"（与"复核"一字之差必混）；词典页不叫"指标"（与验证页撞名）。
- 2026-09-16 预裁决（用户）：**导航两级扁平**——一级：总览/今日/投注/历史/验证/资金；次级（低处/页脚位）：词典/复核（M3 后点亮）/设置；不设组标题。**移动端底线**：所有页可看（表格降级横滚或卡片）、状态/待办/余额一眼可见、单条轻操作可完成（锁纸面注/单场录赛果/结算批跑）；批量录入、逐腿回录、多维筛选等重操作桌面优先，移动可用不优化。

## Answer

2026-09-16 定稿（预裁决 + 草案过审）：

1. **旅程职责 = 每页一个动词**：总览=分诊（数据健康+今日待办，不做操作）、今日=选（机会发现/选注/建建议，不做锁定）、投注=记（锁定/回录/赛果同步/结算全生命周期）、历史=分析（已结算切片下钻）、验证=判（系统级三条件，不做单注分析）、资金=对（真金流水成本）、词典=释（tooltip 就地，不强跳转）。
2. **空状态统一模式 = 一句人话 + 一个动作按钮**，不卖萌不插画：无数据（说明为何空+何时有+刷新）、后端不可用（task server / task ingest-jingcai 指引 + 重试）、功能未达（"复核随 M3 上线"引导态，不装死页）。
3. **路由迁移面最小**：`/` 内容换为总览（今日让位，无重定向破坏）、`/today` 承接今日、新增 `/history` `/glossary`（占位骨架先上）、其余六条路由不动零迁移；e2e 仅 smoke 的 `/` 断言改为总览 + 今日用例迁 `/today`。
