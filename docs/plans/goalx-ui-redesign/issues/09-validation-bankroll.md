# 09 · 验证页与资金页重设计

Type: grilling
Status: resolved
Blocked by: 02

## Question

验证页（指标卡/条件条/收益曲线）与资金页（余额/流水/成本）升级为产品级：

1. 验证页：手写 SVG 曲线换 ECharts 后的形态（滚动/累计双线、回撤区间、条件 markline）；指标分层——首屏结论（验证进度/关键门槛）vs 深度下钻（CLV 明细、样本约束）
2. 弱类型指标（票 34 的 clv/forward 字典）呈现的产品化处理
3. 资金页：余额与流水的可视化（迷你趋势？）、期间成本摘要的信息层级、空状态与首次入金引导
4. 两页各自的空状态（后端不可用/无数据）与加载骨架

## Comments

- 2026-09-16 预裁决（用户）：**验证页首屏 = 一行状态结论（三条件 x/3 + 还差什么）+ 三条件卡 + 前瞻 yield 主图（滚动/累计双线，markline 画 0 基准线——"skill≥0 唯一通过线"可视化）**。下钻层：CLV 明细、样本约束、回测 vs 前瞻对比、条件口径。刻意不上首屏：回测 skill（口径不算数，上首屏是误导）、成本摘要（资金页的事）。

## Answer

2026-09-17 剩余项定稿（用户"全按推荐"）：

1. **弱类型指标呈现**：clv/forward 字典按已知 key 映射为带标签指标行，未知 key 折叠进"其他指标"折叠区——不裸字典直出。
2. **资金页形态**：余额大数字 + 近 30 天余额迷你曲线（ECharts；无流水不显示）；流水 compact 表；成本摘要 ¥ 与 credits 分列，"未记录成本标缺失"警示保留。
3. **入金引导 → 新端点 `POST /api/v1/bankroll/deposits`**：契约目前 bankroll 只读，空资金页的入金引导无落地动作；端点记票 10，随 20 号票内联走 contract-first。
