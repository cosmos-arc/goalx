1. 清单化（已知项先列，2026-09-16 更新）：06 赛果**同步触发/状态端点**（外部依赖：后端源接入在 goalx-quant 地图）、05 总览**待办/聚合端点**、07 历史**查询端点**（分页/过滤/聚合）、04/08/09 暴露的小增量——各自服务的 UX 场景与后端开发量

4. 与 MSW mock、生成的客户端、e2e 的联动改动范围估计

## Answer

2026-09-17 定稿（用户"全按推荐"批准 05-09 各项 + 本票按懒原则收口）：

**增量清单与归属**：

| # | 增量 | 服务 | 归属 |
|---|---|---|---|
| 1 | `POST /api/v1/bankroll/deposits`（入金记录；withdraw 后续按需） | 09/20 资金页入金引导 | **20 号票内联**走 contract-first（export→review diff→codegen 同 commit），后端落 bankroll/资金域（ADR-0008） |
| 2 | `eu_updated_at` 字段（欧赔观测时间） | 14 今日页数据健康行（现为"已接入 N/M 场"近似） | 15 号票若碰 contract 顺带；否则挂起待需要时再加 |
| 3 | 赛果同步触发/状态端点 | 06/16 同步面板 | **外部依赖**：后端源接入（500.com 彩果解析）在 goalx-quant 地图立票；16 号票先做同步面板 UI（状态区显示"后端源未接入，人工兜底"降级态），端点就绪后接 |

**v1 零新端点决定**：总览（05/15）与历史（07/17）均由现有端点前端拼装（bets/bankroll/fixtures/today/validation/draw-results），个人工具数据量千注级无压力；性能不济再加聚合/分页端点。

**排期**：15/16/17 无后端阻塞可立即连跑；contract 变更仅 20 号票一处；同步后端为跨图外部依赖。

**联动范围**：MSW handlers 补 deposits mock（20 号票内）；生成客户端随 codegen 刷新；e2e 无新增契约依赖。
