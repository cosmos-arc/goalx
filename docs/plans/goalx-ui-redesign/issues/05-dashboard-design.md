# 05 · 总览 Dashboard 页设计

Type: grilling
Status: resolved
Blocked by: 03

## Question

新首页（总览）的信息架构：

1. "今天该干什么"待办区：未锁定建议数、待录赛果、待结算、数据新鲜度异常——判定规则与呈现
2. 资金与收益快照：哪些口径上首屏（真金余额/期间盈亏/纸面收益如何共存而不误导）
3. 机会入口：今日可投机会的摘要（几张卡？跳转带不带筛选状态）
4. 下钻路径：每个卡片点击去哪页、带什么上下文
5. 后端缺口（如聚合/待办端点）记入 API 清单（票 10）

## 不变量与人裁决项

- 首屏指标必须附判读方向（涨是好事还是坏事），不得裸放数字——用户指标熟悉度备忘
- 纸面与真金在同屏呈现时必须有视觉隔离，防误读

## Comments

- 2026-09-16 预裁决（用户）：**待办四规则**——①未锁定建议（最早开赛 <2h 标紧迫倒计时）②待录赛果（已过开赛+挂未结注+无赛果的 Fixture）③可结算（全部腿赛果已齐的未结注，提示批跑可落定 N 注）④数据异常（10 点后当日竞彩/欧赔快照仍缺，提示跑 ingest）。**首屏四卡**——真金余额+今日真金盈亏 / 今日纸面盈亏（带"纸面"徽章，与真金不同区不并排）/ 今日可投场次数（带筛选跳今日）/ 真金累计 ROI（附判读与含未结标注）。验证进度页底细进度线（x/3），不占卡位。

## Answer

2026-09-17 剩余项定稿（用户"全按推荐"）：

1. **待办区形态 = 清单卡**：每行 状态点 + 一句话 + 动作链接，按紧迫排序；无待办整卡"今日无事"（克制不庆祝）。不做看板。
2. **下钻路径**：未锁定建议→`/today`；待录赛果/可结算→`/bets` 对应面板；数据异常→就地展开 task 指引（复用 EmptyState）。v1 只跳转不跨页传状态；筛选类下钻待历史页后统一 URL query。
3. **快照卡空态**：未入金→真金卡入金引导（端点见票 10/9.3）；无纸面记录→引导"从今日页建第一笔建议"。
4. **数据源（衔接票 10 定稿）**：v1 全部由现有端点前端拼装（bets/bankroll/fixtures/today/validation），零新聚合端点。
