# Goalx 设计 Spec v1.1 — 可信纸面闭环

2026-09-13：用户在审视及补充调研后要求按“可信纸面闭环”完善计划。本文件是当前计划；[v1.0](spec-v1.0.md)和旧决策票保留历史。依据：[审视报告](../goalx-review-20260913/report.md)、[调研补充](../goalx-review-20260913/research-supplement.md)。术语见[CONTEXT.md](../../CONTEXT.md)，技术决策见[ADR](../../docs/adr/)。

## 1. 目标与不变边界

个人、本地Mac运行，长期盈利导向，允许无候选和不投注；人工下单与真实票据回录，不做自动下单、多用户或SaaS。外部数据预算≤$50/月，本轮不批准新增订阅。保留FastAPI、React、SQLite WAL、Prefect、penaltyblog和契约/CI，不重选框架。

先纸面验证；保留整赛季、CLV不少于200注且beat≥60%、skill≥0、复核无系统性错误的既定约束。本阶段不做真钱推荐放行，不以短期运行代替长期验证。阈值是必要诊断条件，不能单独证明盈利或样本独立性。

## 2. 当前能力与验收状态

M1/M2已合并：竞彩/欧赔/历史采集、DC训练、Forecast、合成报价回测、页面与部分结算。代码完成不等于业务验收。本次审视时本机库有39场Fixture、26场欧赔关联、16条Forecast，Bet/DrawResult/CLV/closing快照为0；这是2026-09-13快照，不能代替后续查询。

票33已实现结算/资金生命周期纠偏并通过本地task check（179后端测试、94.17%覆盖率，19前端测试、契约与4项浏览器冒烟）；不是完整业务闭环证据。待完成：可靠浏览器闭环、赛前证据/统计、连续采集与真实收盘验收。奖池为部分判定原型，LLM/复核/完整成本纪律仍未完成。旧票保留原答案，新修订段说明未验收项目和后继票。

## 3. 假设与优先顺序

| 方向 | 当前定位 | 下一步 |
|---|---|---|
| A：国内报价滞后于有效国际信息 | 待验证，无频率/收益承诺 | 限定赛事的同步报价和had纸面观察优先 |
| B：滚存与公众份额偏差 | 待验证，分奖模型和数据不完整 | 暂缓优化器，后续先核验数据 |
| ML概率 | 已有研究基座 | 修时点、版本、评分，保留市场/ML独立比较 |
| LLM情报 | 无本项目增量价值证据 | 后续先小范围情报评测，暂缓完整融合 |

撤下“每轮1–5场、收益1–5%、滚存5–20%、组合低个位数收益”的计划默认，保留原研究中的历史假设。不用这些数设预算或验收。去水概率是估计，公众人气不是已验证资金份额。DC是否超过市场不阻止独立的市场驱动陈盘纸面研究；不得因此降低使用ML定价所需的验证。

## 4. 最小产品范围

新建正式纸面选择先限had：具备单固资格可单关；否则仅在不同比赛共同可购买的时点形成合法2串1。无第二腿或资格未知时不强行生成。禁同场串关、3串以上；已有其他玩法记录保留，不支持的路径明确限制。

今日→选择/锁定→开奖→结算→收益与CLV复盘，通过浏览器完成，用队名与销售编号，不要求手查数据库ID。保存原建议与实际回录的价格/金额/时间差异。未购建议、正式锁定纸面、实际购买分开；反事实统计不混入正式成绩，paper不产生真钱流水。

页面显示来源、时点、销售资格、缺失及拒绝原因；负EV偏差不冒充正EV机会。成本先做期间台账和总成本摘要，currency与credits分单位，缺失明确显示，不先建设完整设置中心。

## 5. 数据与时间约束

内部Fixture ID稳定，供应商ID作外部映射；已知主客队/ID交叉验证，赛事+时间窗仅作候选匹配，歧义拒绝，改期保持同一业务身份。这替代v1.0把API-Football直接当canonical标识的绑定，不需要迁移现有内部ID。

区分source_updated_at、observed_at、入库时间；历史接口保存实际返回snapshot时间。源时间未知可空，不能伪造；源更新早不代表系统当时已知。保存脱敏原始响应或文件引用/哈希和解析版本；历史回放与实时观测分开。

保存销售状态、had单固资格、让球和价格语义；核验比赛范围。国际大小球不能直接当竞彩进球桶，亚洲让球不等于三向让球。真实totals/handicap接入不是恢复其他玩法的充分条件。

正式候选要求同义市场、同公司完整三向、可信匹配、有效新鲜度和两源时差；不合格只观察不推荐。工程初始新鲜度/配对时差上限各5分钟，可配置但不作为成交保证，不自动放宽以凑验收。旧数据不能证明observed_at时不倒填前瞻资格。采样不足如实报告。

haircut按同一as-of配对，分列场次数与选择数。离线核验自写Shin与库实现，比较归一化/Power以及先逐公司去水再聚合；固定方法与版本，不事后挑最赚钱的方法。

## 6. 模型、回测与验证

DC及全场比分矩阵保留，had/hhad/ttg/crs由其推导；半全场需额外过程假设，0.45半场拆分仅为近似，本轮不认证其可投注性。

正式Forecast的训练窗口与生成时间均早于kickoff；赛后replay独立标记。模型身份含数据、配置、实现/依赖版本，旧工件不被不同配置覆盖；本轮不升级penaltyblog。

回测继续had-only，定位为模型与合成报价实验。市场估计概率p、折价h对应模拟十进制赔率`O_sim=(1-h)/p`。模型训练窗无前视不等于周内最终收盘挑串关可执行；不能用此实验证明真实竞彩陈盘或资金纪律有效。

历史基准按来源/日期质检，复查football-data自2025-07-23后的PSC质量。旧run保留，对照产生新run，不无条件以PSC或AvgC充当真概率。相关性未处理的p值标探索性；先修排序、分母、重复计数。bootstrap标名义水平与有效样本数，覆盖未验证不得声称校准成功。

回测/前瞻分栏；前瞻按固定策略/模型版本和纳入规则分组。paper/live/未购分开，票/腿/场次数分列，200注不能用200腿代替。滚动100注按唯一正式纸面Bet统计。

CLV只用完整赛前有效报价，记录源、时间与缺失率；无数据不是零或通过。单关与2串1分开；2串1按票级联合概率评估并标独立性假设，腿级仅诊断，不复制整票profit做独立回归。无复核记录=未评估；整赛季独立显示，历史回测skill不能充当前瞻skill。

## 7. 结算、资金与成本

无效串关腿按赔率1，剩余有效腿依原报价/赛果结算，不能因只剩一腿整单退款；单关无效或全无效返本金。实际购买是受状态约束的幂等转换；只有已购live产生真钱支出/兑付。

DrawResult是开奖结算事实，更正保留旧新审计，受影响已结记录重算并差额冲正，不覆盖资金历史。记录真实历史票据与系统真钱推荐资格分开，不能因为模型未通过就禁止如实记账。

奖池需考虑各奖级、共同中奖分奖与可分配资金；不把独中公式或边际人气乘积包装成已验证EV。未获奖金资料保持待结算，不能写0元已完成。

最小成本模块提前：期间费用与用量、收益和缺失项分列。固定费用不任意按预计注数当边际成本，不以凑换手率为目标。原1/4 Kelly、单注1%、分配与熔断设计留作长期要求，本轮不声称已实施完整真钱纪律。

## 9. 暂缓与后续决策

M3完整LLM与M4全玩法/奖池优化改为暂缓方向，不是承诺顺序。完成本阶段后，基于覆盖、可观察性与成本再决定一项扩展。

LLM先证明少量带来源/时点的情报有新增价值，自动概率调整另行验证；奖池先证明奖级/分奖规则、池数据及公众份额误差可评估。sports-betting、footBayes、更多模型、新订阅都不是前置。

没有信号如实记录，样本不足与假设失败分开，不通过扩大模型或下注凑结果。整赛季通过口径的进一步统计细化、扩展触发阈值由真实证据与后续用户裁决确定，当前保留未知而非自动通过。
